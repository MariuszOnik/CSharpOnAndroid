1. Pierwsza gra

class MojaGra : GameScript
{
    Vector2 kulka;

    public override void Start()
    {
        Background = Color.DarkSlateBlue;
        kulka = new Vector2(Width / 2, Height / 2);
    }

    public override void Update(float dt)
    {
        if (IsTouching)
            kulka = TouchPosition;   // kulka idzie za palcem
    }

    public override void Draw()
    {
        FillRect(kulka.X - 40, kulka.Y - 40, 80, 80, Color.Orange);
        DrawText("Dotknij ekranu", 30, 60, 48, Color.White);
    }
}

System, System.Collections.Generic, System.Linq,
Microsoft.Xna.Framework, Microsoft.Xna.Framework.Graphics,
Microsoft.Xna.Framework.Input.Touch, GameApi

Inne dopisz na górze pliku, np. using System.IO;, using System.Diagnostics;, using Microsoft.Xna.Framework.Audio;.

2. Cykl życia: Start, Update, Draw

MetodaKiedyDo czego
Start()raz, na początkuwczytanie obrazków, utworzenie obiektów, ustawienie tła. Width/Height już działają.
Update(float dt)ok. 60 razy na sekundęlogika: ruch, dotyk, kolizje, punkty. dt = sekundy od poprzedniej klatki (zwykle ~0,0167).
Draw()po Update, gdy jest czas na rysowanietylko rysowanie. Ekran jest już wyczyszczony kolorem Background.
  • Ruch mnóż przez dt: x += 300 * dt; to 300 pikseli na sekundę niezależnie od FPS.
  • Gdy telefon nie wyrabia, MonoGame wywołuje kilka razy Update i pomija Draw. Dlatego w Draw nie zmieniaj stanu gry (nie licz punktów, nie przesuwaj obiektów).
  • Kolejność rysowania = kolejność wywołań: to, co narysujesz później, jest na wierzchu.

3. Jeden punkt wejścia

Tak – gra ma dokładnie jeden punkt wejścia: jedną klasę dziedziczącą po GameScript. Aplikacja tworzy jej obiekt i to tylko jej Start, Update i Draw wywołuje sama.

  • Brak takiej klasy → błąd „Brak klasy dziedziczącej po GameScript”.
  • Dwie takie klasy (nawet w różnych plikach) → błąd „Więcej niż jedna klasa dziedziczy po GameScript”.
  • Nazwa klasy i pliku nie ma znaczenia.

4. Wiele klas i plików

Każda klasa może mieć własne Update i Draw, ale nikt ich nie wywoła automatycznie. Wywołujesz je sam z głównej klasy. Takie klasy nie dziedziczą po GameScript – to zwykłe klasy C#. Plików może być dowolnie wiele (zakładka +), wszystkie są kompilowane razem.

Sposób A: przekaż grę w konstruktorze

// Gracz.cs
class Gracz
{
    readonly GameScript gra;
    public Vector2 Pozycja;

    public Gracz(GameScript gra)
    {
        this.gra = gra;
        Pozycja = new Vector2(gra.Width / 2, gra.Height - 200);
    }

    public void Update(float dt)
    {
        if (gra.IsTouching)
            Pozycja = Vector2.Lerp(Pozycja, gra.TouchPosition, 10 * dt);
    }

    public void Draw() => gra.FillRect(Pozycja.X - 50, Pozycja.Y - 20, 100, 40, Color.Orange);
}

// Gra.cs – jedyny punkt wejścia
class Gra : GameScript
{
    Gracz gracz;

    public override void Start() => gracz = new Gracz(this);
    public override void Update(float dt) => gracz.Update(dt);
    public override void Draw() => gracz.Draw();
}

Sposób B: lista obiektów ze wspólną klasą bazową (polecany)

Mini system obiektów: każdy obiekt ma swoje Update/Draw, a gra obsługuje całą listę.

// Obiekt.cs
abstract class Obiekt
{
    public static Gra Gra;          // ustawiane w Gra.Start – dostęp do rysowania i dotyku
    public Vector2 Pozycja;
    public bool DoUsuniecia;

    public virtual void Update(float dt) { }
    public virtual void Draw() { }
}

// Pocisk.cs
class Pocisk : Obiekt
{
    public Vector2 Predkosc = new Vector2(0, -900);

    public override void Update(float dt)
    {
        Pozycja += Predkosc * dt;
        if (Pozycja.Y < -20) DoUsuniecia = true;
    }

    public override void Draw() => Gra.FillRect(Pozycja.X - 4, Pozycja.Y - 12, 8, 24, Color.Yellow);
}

// Gra.cs
class Gra : GameScript
{
    public readonly List<Obiekt> Obiekty = new();
    readonly List<Obiekt> nowe = new();

    public void Dodaj(Obiekt o) => nowe.Add(o);   // bezpieczne także w trakcie pętli

    public override void Start()
    {
        Obiekt.Gra = this;
    }

    public override void Update(float dt)
    {
        if (JustTouched)
            Dodaj(new Pocisk { Pozycja = TouchPosition });

        foreach (var o in Obiekty) o.Update(dt);
        Obiekty.RemoveAll(o => o.DoUsuniecia);
        Obiekty.AddRange(nowe);
        nowe.Clear();
    }

    public override void Draw()
    {
        foreach (var o in Obiekty) o.Draw();
        DrawText($"Obiekty: {Obiekty.Count}", 30, 60, 40, Color.White);
    }
}
Nie dodawaj ani nie usuwaj elementów listy wewnątrz foreach po tej samej liście – C# rzuci wyjątek. Dlatego nowe obiekty trafiają najpierw do nowe, a usuwanie robi RemoveAll po pętli.

Pole static jest bezpieczne: przy każdym „Graj” kod jest kompilowany od nowa, więc statyczne pola startują czyste.

5. Ekran, kolory, współrzędne

  • (0, 0) to lewy górny róg, X rośnie w prawo, Y w dół. Jednostka = piksel ekranu.
  • Width, Height – rozmiar ekranu. Telefon można obrócić, więc czytaj je na bieżąco zamiast zapamiętywać raz.
  • Background – kolor tła, np. Background = new Color(20, 24, 40);
  • Kolory: Color.Red, new Color(255, 128, 0), new Color(1f, 0.5f, 0f).
  • Półprzezroczystość: Color.Black * 0.5f (mnożenie, nie new Color(r,g,b,a) – patrz pułapki).
  • Mieszanie: Color.Lerp(Color.Red, Color.Blue, 0.3f).
  • Fps – aktualna liczba klatek na sekundę.

7b. Sprite'y: atlas, pivot, animacja

Sprite to wycinek obrazka (np. jedna klatka z atlasu) z pivotem – punktem zaczepienia. Pozycja, którą podajesz przy rysowaniu, to miejsce pivota; obrót i skala też są wokół niego.

PivotZnaczenie
(0, 0)lewy górny róg (jak DrawImage)
(0.5, 0.5)środek – domyślny; dobre dla pocisków, kół, obracanych rzeczy
(0.5, 1)środek dołu – stopy postaci, drzewa, budynki stojące na ziemi
(0, 0.5)lewy środek – np. lufa obracana wokół podstawy

Atlas pocięty na siatkę

Sprite[] bohater;                     // np. bohater.png: 4 kolumny × 2 rzędy klatek 32×32

public override void Start()
{
    bohater = LoadSprites("bohater.png", 32, 32, new Vector2(0.5f, 1f));   // pivot w stopach
    // klatki numerowane wierszami: 0..3 – pierwszy rząd, 4..7 – drugi
}

public override void Draw()
{
    DrawSprite(bohater[0], pozycja, scale: 4);
}

Atlas z odstępami (np. paczki Kenneya): LoadSprites("tiles.png", 16, 16, margin: 0, spacing: 1). Masz już wczytany obrazek? Sprite.Slice(obrazek, 32, 32).

Animacja

float czas;
bool wLewo;

public override void Update(float dt)
{
    czas += dt;
    if (IsTouching) wLewo = TouchPosition.X < pozycja.X;
}

public override void Draw()
{
    var bieg = bohater[4..8];                          // klatki 4,5,6,7 (drugi rząd)
    var klatka = Sprite.Animate(bieg, czas, 10);       // 10 klatek na sekundę, w pętli
    DrawSprite(klatka, pozycja, scale: 4, flipX: wLewo);   // odbicie w poziomie
}

Sprite.Animate(klatki, czas, fps, loop: false) zatrzymuje się na ostatniej klatce (wybuch, śmierć) – licz wtedy czas od początku tej animacji.

Przy flipX/flipY pivot też się odbija, więc postać z pivotem w stopach nie „skacze” przy obrocie w drugą stronę.

Wszystkie warianty DrawSprite

DrawSprite(s, x, y);                                   // pivot w (x, y)
DrawSprite(s, x, y, 2f);                               // skala
DrawSprite(s, poz, obrot, skala, Color.Red, flipX: true, flipY: false);
DrawSprite(s, poz, new Vector2(1.2f, 0.8f));           // osobna skala X i Y („spłaszczenie” przy lądowaniu)
DrawSprite(s, poz, color: Color.White * 0.5f);         // półprzezroczysty

Ręczny wycinek i własny pivot

Texture2D atlas = LoadImage("atlas.png");
var miecz  = new Sprite(atlas, new Rectangle(64, 0, 16, 48), new Vector2(0.5f, 0.9f));  // obrót wokół rękojeści

var drzwi  = new Sprite(atlas, new Rectangle(80, 0, 32, 48)).SetPivotPixels(16, 46);    // pivot w pikselach wycinka
var drugi  = miecz.WithPivot(0.5f, 0.5f);           // ta sama klatka, inny pivot

Bez obiektu Sprite: DrawImage(atlas, new Rectangle(32, 0, 32, 32), poz, new Vector2(0.5f, 1f), rotation: 0, scale: 3, flipX: true);

GameScript to tylko wygodna nakładka. Pod spodem jest pełna biblioteka MonoGame 3.8 – masz dostęp do Batch (SpriteBatch), GraphicsDevice i Pixel, więc możesz używać jej bezpośrednio.

Ostre piksele (pixel art) i kamera

Aplikacja otwiera Batch przed Draw() z ustawieniami domyślnymi (wygładzanie, bez kamery). Możesz go zamknąć i otworzyć po swojemu – na końcu otwórz go ponownie zwykłym Batch.Begin(), bo aplikacja dorysowuje jeszcze przycisk ✕ i sama woła End().

public override void Draw()
{
    var kameraM = Matrix.CreateTranslation(-kamera.X, -kamera.Y, 0) * Matrix.CreateScale(zoom);

    Batch.End();
    Batch.Begin(samplerState: SamplerState.PointClamp, transformMatrix: kameraM);
    // ... świat gry: współrzędne świata, ostre piksele ...
    Batch.End();

    Batch.Begin();
    // ... interfejs: współrzędne ekranu (punkty, przyciski) ...
}

// Dotyk w współrzędnych świata:
var swiat = Vector2.Transform(TouchPosition, Matrix.Invert(kameraM));

Inne opcje Batch.Begin: blendState: BlendState.Additive (świecenie, ogień), sortMode: SpriteSortMode.BackToFront (sortowanie po parametrze layerDepth).

Tekstury z kodu

Texture2D Kolo(int r, Color kolor)
{
    var t = new Texture2D(GraphicsDevice, r * 2, r * 2);
    var piksele = new Color[r * 2 * r * 2];
    for (int y = 0; y < r * 2; y++)
        for (int x = 0; x < r * 2; x++)
            if ((x - r + 0.5f) * (x - r + 0.5f) + (y - r + 0.5f) * (y - r + 0.5f) <= r * r)
                piksele[y * r * 2 + x] = kolor;
    t.SetData(piksele);
    return t;
}
// Start:  kolo = Kolo(32, Color.White);   Draw: Batch.Draw(kolo, poz, Color.Red);

Proste 3D

    new VertexPositionColor(new Vector3(1, -1, 0), Color.Green),

IsoWorldprzeliczanie kratek izo (x, y, z) ↔ piksele. new IsoWorld(tileSize, tileHeight, tileRatio = 0.5f, tileAngle = 45f), Origin – gdzie na ekranie leży (0,0,0), ToScreen(Vector3), ToIso(Vector2 ekran, z = 0)
IsoObjectprostopadłościan: Position (minimalny róg w kratkach), Size (x, y, z), Sprite, Color, IsMoving (ruchome sortowane co klatkę), Name
IsoSorterSort(obiekty, minX, minY, maxX, maxY) – zwraca widoczne obiekty w kolejności rysowania (od najdalszego). Prostokąt widoku w pikselach świata. InvalidateStatic() po zmianie nieruchomych obiektów.
IsoSpriteIsoSprite.CreateBox(GraphicsDevice, world, rozmiar, out offset) – generuje teksturę klocka (biała z cieniowaniem, kolor nadajesz przy rysowaniu)
IsoWorld world = new(32, 32);
IsoSorter sorter;
List<IsoObject> obiekty = new();
Dictionary<Texture2D, Vector2> przesuniecia = new();
IsoObject gracz;

public override void Start()
{
    world.Origin = new Vector2(Width / 2, 300);
    sorter = new IsoSorter(world);

    var klocek = IsoSprite.CreateBox(GraphicsDevice, world, new Vector3(1, 1, 1), out var off);
    przesuniecia[klocek] = off;
    for (int x = 0; x < 8; x++)
        for (int y = 0; y < 8; y++)
            if (Random.Next(4) == 0)
                obiekty.Add(new IsoObject { Position = new Vector3(x, y, 0), Size = Vector3.One, Sprite = klocek, Color = Color.SandyBrown });

    var maly = IsoSprite.CreateBox(GraphicsDevice, world, new Vector3(0.4f, 0.4f, 0.8f), out off);
    przesuniecia[maly] = off;
    gracz = new IsoObject { Position = new Vector3(0, 0, 0), Size = new Vector3(0.4f, 0.4f, 0.8f), Sprite = maly, Color = Color.Red, IsMoving = true };
    obiekty.Add(gracz);
}

public override void Update(float dt)
{
    if (IsTouching)
    {
        var cel = world.ToIso(TouchPosition);         // kratka pod palcem
        var p = gracz.Position;
        gracz.Position = Vector3.Lerp(p, new Vector3(cel.X, cel.Y, 0), 3 * dt);
    }
}

public override void Draw()
{
    foreach (var o in sorter.Sort(obiekty, 0, 0, Width, Height))
        Batch.Draw(o.Sprite, world.ToScreen(o.Position) + przesuniecia[o.Sprite], o.Color);
}

14. Czego nie ma

  • Content Pipeline – Content.Load, pliki .xnb, SpriteFont. Obrazki: LoadImage, tekst: DrawText.
  • Własne shadery – nie ma kompilatora efektów. Zostają wbudowane (BasicEffect itd.) i BlendState.
  • Dostęp do obiektu Game – nie wyjdziesz z gry kodem (Exit()), nie zmienisz liczby klatek. Wyjście: ✕ albo Wstecz.
  • Klawiatura, mysz, pad – tylko dotyk.
  • Komponenty MonoGame (GameComponent, DrawableGameComponent) – zamiast nich wzorzec z rozdziału 4.
  • Muzyka MP3 (Song, MediaPlayer) – raczej nie zadziała.
  • Czujniki (akcelerometr) – MonoGame 3.8 ich nie ma.

15. Błędy i pułapki

  • Błąd kompilacji – lista pod edytorem, dotknij wiersza, żeby skoczyć do pliku i linii. Zakładka z błędem jest czerwona.
  • Wyjątek w trakcie gry (np. NullReferenceException, brak obrazka) – gra się zamyka, a w edytorze pojawia się „Błąd w trakcie gry: …”. Najczęściej: pole nie zostało ustawione w Start.
  • Podgląd wartości – nie ma debuggera, więc wypisuj zmienne na ekran: DrawText($"x={x:0.0} v={v}", 20, 200, 32, Color.Yellow);
  • Nie twórz tekstur w Draw/Update (LoadImage, new Texture2D, new RenderTarget2D) – rób to raz w Start. Niepotrzebną teksturę zwolnij: tekstura.Dispose().
  • Przezroczystość – kolory są „premultiplied”: używaj kolor * 0.5f. new Color(255, 0, 0, 128) wyjdzie jaśniejszy niż powinien.
  • Pętla nieskończona w Update zawiesza aplikację – trzeba ją zamknąć z systemu.
  • Vector2.Normalize(Vector2.Zero) daje NaN i obiekt znika – sprawdzaj długość przed normalizacją.
  • Dzielenie całkowite: Width / 3 to int; 1 / 2 = 0. Pisz 1f / 2.
  • JustTouched w Draw może przegapić klatkę – sprawdzaj dotyk w Update.
  • Wydajność: unikaj new List, LINQ i łączenia stringów w każdej klatce przy tysiącach obiektów. Kilkaset obiektów to nie problem.
